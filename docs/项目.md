# AgentTeams Dashboard 项目（Projects）使用指南

本文档面向使用 Dashboard 监控和干预 AgentTeams 项目的运维与平台使用者：项目是什么、从哪里来、怎么查、怎么暂停/恢复/重规划、怎么下载产物、怎么看历史。

> 开发者视角（组件结构、API 客户端、缓存策略、扩展点）见 [`项目开发.md`](./项目开发.md)。

## 1. 项目是什么

AgentTeams 中的「项目」是一次**有结构、有目标、可被人为干预**的工作流编排产物，由 Manager（Leader）通过 `TeamHarness.projectflow` 流程生成，最终落到 `shared/projects/{id}/meta.json` 并通过 Controller 暴露为标准 API。

每个项目有：

- **唯一 id**（在某个 team 范围内唯一；同一 id 可在不同 team 下存在）
- **状态**：`planning` / `active` / `paused` / `completed` / `unknown`
- **计划类型**：`dag`（有向无环图，节点之间有依赖） / `loop`（迭代循环）
- **模式**：`project`（标准项目） / `quick`（快速模式）
- **任务节点**（node）：每个节点会被分配给团队内的某个 Worker 执行
- **依赖边**（edge）：节点之间的执行先后关系

Dashboard 的「项目」页**只读 + 干预**，不负责创建项目。创建项目的入口在 Matrix 房间里的 Manager（详见第 3 节）。

## 2. 入口与界面

**入口**：侧边栏 → **项目**（位于「运行时」分组）

**三视图**（顶部切换）：

| 视图 | 何时用 | 看到什么 |
|---|---|---|
| **列表** | 想看某个项目的完整细节、干预它、查历史 | 左侧项目列表 + 右侧详情面板（节点 / 中断 / 任务详情 / 产物 / 干预记录） |
| **卡片** | 浏览式查看所有项目 | 卡片网格 + 选中后的详情 |
| **拓扑** | 看任务依赖关系 | 左侧项目列表 + 右侧依赖图 SVG（不显示详情面板） |

**自动刷新**：列表和详情每 15 秒轮询（`useProjects` / `useProjectWorkflow`）。需要立即刷新可点详情面板右上角的刷新按钮。

## 3. 怎么创建项目

Dashboard **没有「新建项目」按钮**。项目的唯一来源是 `TeamHarness.projectflow`，由 Manager（Leader）触发。

**最简路径**：

1. 侧边栏 → **聊天** → 进入任意带 Manager 的 Matrix 房间
2. 发送指令（把 `<填你的目标>` 替换成具体内容）：

   ```
   用 projectflow 创建一个 dag 项目：<填你的目标>，拆成 3 个有依赖的任务，团队用默认团队。
   ```

3. 等待 15 秒内自动出现在「项目」页

**指令模板**（按复杂度递增）：

- 极简：`帮我创建一个项目：<一句话目标>，分解成 3 个任务。`
- 标准：`请创建一个新项目：目标=<...>，计划类型=dag，任务数=3-5，团队=<team_id 可选>`
- 完整：指定每个任务的标题、负责人、依赖关系、验收标准（参考 `projects-section.tsx:978` 的空态文案）

**先看 plan 再落盘**（推荐第一次用）：

```
帮我用 projectflow 创建一个项目：
1. 先给我一个简短的实施计划
2. 我确认后，再分解成具体任务写入 shared/projects/
```

**失败处理**：

| 现象 | 原因 | 处理 |
|---|---|---|
| 15s 后项目页仍为空 | Manager 还在拆解 / 未触发 projectflow | 在聊天里追问"请直接落盘" |
| 顶部黄色降级横幅 | Controller 未升级到含项目 API 的版本 | 找运维升级 Controller |
| 任务全是 `pending` 不动 | 团队里没有对应 Worker | 侧边栏「团队」→ 给团队补齐 Worker |
| 409「项目 id 在多个团队下存在」 | 同一 project_id 在两个 team 下重复 | 选带正确 team 标签的条目 |

## 4. 查看项目详情

选中一个项目后，详情面板（从左到右、从上到下）展示以下区块：

1. **标题 + 状态徽标** + 「暂停 / 重规划 / 刷新」按钮
2. **中断区**（paused 时出现）：展示 `pause_reason` 与「恢复执行」按钮（条件是 `interrupts` 命中 `allow_accept: true`）
3. **Loop 进度**（loop 类型项目专属）：进度条 + `current_iteration / max_iterations` + 目标说明 + 当前迭代的任务列表
4. **下一步**（`wf.next`）：依赖全完成、当前可执行的任务徽标
5. **任务分布**：按状态统计的徽标（待办 / 已派发 / 执行中 / 已完成 / 需修订 / 阻塞）
6. **任务详情**：每个任务的元数据 + 产物下载链接 + 「取消任务」按钮（非终态任务可见）
7. **干预记录**（折叠面板）：见第 7 节
8. **节点**：所有节点的卡片网格（id / 名称 / 负责人 / 状态）

**复合身份注意**：每个项目以 `(team, project_id)` 复合定位。同一 id 跨团队存在时，左侧列表会显示多条，**必须选带正确 team 标签的条目**。如果列表只显示一条但 workflow 接口 409，需要在 Controller 侧核对 `meta.json` 的 team 归属。

## 5. 怎么干预项目

详情面板右上角提供三类写操作：

### 5.1 暂停（pause）

- **入口**：详情面板「暂停」按钮（`active` 或 `planning` 状态可见）
- **必填**：可选的 `reason`（Dialog 里填写，会写到 `meta.json` 的 `pause_reason` 字段）
- **后端**：`POST /api/agentteams/projects/{id}/pause`
- **冲突**：409「项目已暂停」/ 403 跨团队 → toast 显示 Controller 原始错误信息

### 5.2 恢复（resume）

- **入口 A**：详情面板「恢复执行」按钮（仅当 `interrupts` 中存在 `action_request.action === 'resume'` 且 `config.allow_accept === true` 时显示）
- **入口 B**：直接调 API（不经过 UI）
- **后端**：`POST /api/agentteams/projects/{id}/resume`
- **冲突**：409「项目未暂停」/ 403 跨团队

### 5.3 重规划（replan）

- **入口**：详情面板「重规划」按钮（仅 `active` 状态的 dag 项目可见）
- **输入**：JSON 数组，Dialog 默认从当前 workflow 生成可编辑的 seed（`projects-section.tsx:444-462`）
- **字段命名**：使用 `taskId / title / assignedTo / dependsOn` 命名空间（与 Controller 的 snake_case 在 client 侧做映射）
- **后端**：`POST /api/v1/projects/{id}/replan`
- **校验**：Controller 端会校验重复 task_id、未知依赖、循环依赖；不通过返 409
- **副作用**：会覆盖原 plan；in-flight 任务如果 id 与新 plan 重复则保留原 status

### 5.4 取消单个任务

- **入口**：「任务详情」区的「取消任务」按钮（终态任务不显示）
- **必填**：`reason`
- **可选**：`replacementTaskId`（替换任务时使用）
- **后端**：`POST /api/v1/projects/{id}/tasks/{taskId}/cancel`
- **冲突**：409 终态任务 / 404 任务不在图内 / 400 缺 reason

## 6. 下载产物

每个任务的「任务详情」行展示产物下载链接：

- **结果文件**：`task.result_path` → 走 `GET /api/agentteams/projects/{id}/tasks/{taskId}/artifact`
- **多个交付物**：`task.deliverables[]` → 同一端点 + `?path=` 参数逐个下载

下载走浏览器流式下载（非 fetch 后转 blob），中文文件名通过 RFC 5987 `Content-Disposition` 保留。如果 Controller 返 4xx/5xx，toast 会显示 Controller 返回的原始错误信息（不会把错误体当文件下载）。

## 7. 干预记录（项目时间线）

**入口**：详情面板最下方 → 「**干预记录**」折叠按钮

**展示内容**：

- 列表：每次人工干预（暂停 / 恢复 / 重规划）前的 workflow 快照元数据，按时间倒序
- 单条详情：状态、标题、操作人、操作时间、暂停原因

**触发端点**：

```
GET /api/agentteams/projects/{id}/history?team={teamId}
GET /api/agentteams/projects/{id}/history/{ts}?team={teamId}
```

**行为**：

- 第一次展开时懒加载（不预取）
- 面板关闭 / 组件卸载时 `AbortController.abort()` 自动取消未完成请求
- Controller 404（API 未部署）→ 显示「Controller 升级后可见」灰色文案，不阻塞项目主流程
- 没有干预记录 → 显示「暂无干预记录」

## 8. 与任务看板的联动

侧边栏「**任务看板**」页（D5/D8 自 v1.2.3.1 起）的**主数据源**就是 Controller projects API：

- 列表里看到的项目 = 侧边栏「项目」页的同一份数据
- 看板列出的任务 = Controller `getProjectWorkflow(includeTasks=true)` 返回的 `tasks_detail` + 依赖边（`useApiTaskBoard.workflowToBoard` 重建 `dependsOn`）
- 每次暂停/恢复/重规划/取消任务后，看板通过 TanStack Query 缓存键 `['agentteams-project-workflow', teamId ?? 'any', projectId]` 立即回写，无需手动刷新
- 当 Controller API 降级（404 / 5xx / 网络断）时，看板自动 fallback 到 MinIO 直读，UI 不空白

## 9. 降级与告警语义

| 场景 | 表现 | 含义 |
|---|---|---|
| 项目页顶部黄色横幅 + `degraded: true` + `degradedReason: 'api-not-deployed'` | Controller 没装项目 API（PR `#1169` 未合或 Controller 未升级） | 列表/详情不可用，等 Controller 升级 |
| 项目页顶部黄色横幅 + `degradedReason: 'controller-error'` | Controller 端点存在但调用失败（典型：MinIO 不可达） | 后端故障，查 Controller 日志 |
| 详情面板「无法加载项目工作流（项目不存在或 API 不可用）」 | 404 / 5xx 非降级路径 | 项目 id 错或后端故障 |
| 详情面板「该项目 id 在多个团队下存在」 | 409 | 复合身份歧义，按第 4 节末尾处理 |
| 时间线面板「Controller 升级后可见」 | Controller 缺 history 端点 | 不影响主流程 |

## 10. 常见问题

**Q：项目能删除吗？**
A：当前 Dashboard 没有删除入口；Controller 端可调用 `DELETE /api/v1/projects/{id}`（如果已部署）。删除是破坏性操作，建议先暂停确认不再需要。

**Q：状态卡在 `paused` 怎么恢复？**
A：详情面板有「恢复执行」按钮时点它；没有就检查 Manager 是否在线（侧边栏「Managers」页）。

**Q：replan 后任务状态不对？**
A：Controller 保留与新 plan 同 id 的旧 status，其余任务按新 plan 初始状态。如果新 plan 漏了某些 id，对应任务会保留原状态（不重新初始化）。

**Q：为什么时间线面板里有快照但详情里没有对应记录？**
A：时间线是「干预前快照」，不是「干预后状态」。要看当前状态直接看详情面板。

**Q：loop 类型项目的「下一步」为什么一直是同一组？**
A：loop 类型的 next 在每次迭代结束时刷新；如果 `current_iteration === max_iterations`，loop 结束并转为 `completed`。
