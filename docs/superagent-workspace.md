# Agent 工作区

登录后的主入口是与 Agent 的持续对话。平台管理员使用平台助手，团队用户使用已有的 Team Leader 私聊。对话仍由原有服务承载，不创建另一套会话或任务数据。

## 入口与权限

- 打开产品根路径时进入对话；带有页面或会话标识的深链接继续生效。
- 管理员优先打开平台 Manager 的对话。
- 「助手」只展示平台助手和当前账号担任 Team Admin 的 Leader 私聊，并以实际 Matrix 入群状态校验，不依赖全局 Manager 列表。
- 「我的团队」展示当前账号已加入的所有团队工作群，每个团队分别标明「管理员」或「成员」。同一账号可同时管理多个团队并作为普通成员加入其他团队；管理员私聊不会出现在普通成员的入口中。
- Team Leader 的身份与运行时优先由现有 Worker 数据补全，兼容 Manager 作为 Leader 的数据。
- 非管理员不请求全局 Managers、Humans，平台助手也不会作为团队用户的默认入口。
- 所有操作继续使用原有登录、服务端权限校验和 Controller 凭据。
- Leader DM 的实际访问仍由房间成员权限决定：当前 Controller 为 Team Admin 与 Leader 建立私聊，旧团队回退为平台 Admin 与 Leader；团队资源可见不等于已加入该私聊。

## 界面结构

任务便签、任务、成员、文件、话题与概览集中在右侧切换，聊天顶部只保留助手信息和侧栏入口。侧栏收起后保留图标快捷入口。

内置全局管理员也有自己的 Human 文件区。用户管理列表隐藏 `systemAdmin` 记录；个人文件页按当前 Matrix 身份优先打开本人的文件区，聊天附件保存也按该身份解析 Human，不依赖登录名与资源名相同。

| 位置 | 内容 |
| --- | --- |
| 助手 | 平台助手或当前账号管理团队的 Leader 私聊；「团队协作」跳转对应团队工作群 |
| 我的团队 | 已加入的全部团队工作群及各自角色；普通成员只有群聊，Team Admin 可返回自己的 Leader 助手 |
| 工作台 | 左侧子菜单：待你处理、任务看板、产物、编码执行、自动化 |
| 资产中心 | 左侧子菜单：模型、工具、技能、知识库；工具复用原 MCP 管理 |
| 成员与团队 | 左侧子菜单：Agent、团队、用户与 Manager；管理功能及权限范围不变 |
| 设置 | 左下常驻；管理页提供总览、审计及插件贡献的监控、诊断等入口；插件页保留插件目录、安装与配置 |
| 顶栏 | 全局搜索、创建、通知、账号、主题、设置和插件工具 |
| 对话侧面板 | 任务、成员、文件、话题、空间概览 |

全部对话列表通过「切换对话」展开。协议名称不占据主对话界面，消息服务配置保留在高级连接设置中。Worker 头像的运行时会话入口仍然保留。

桌面侧栏与移动导航抽屉共用五个主菜单：助手、我的团队、工作台、资产中心、成员与团队。后面三个菜单点击展开或收起子菜单，子页面直接在左侧选择。侧栏整体仍可收起为图标，点击分组图标先展开导航。插件菜单保留在设置中。原有 section 和深链接继续保留；新增 `#workbench/teams` 进入我的团队，旧群聊深链接自动转入团队视图。设置中打开审计、总览或插件页面会先关闭设置弹窗；键盘主导航快捷键与五项菜单对应。

AT 绿色为默认主色；亮色、暗色、高对比度和企业主题继续使用原有主题机制。桌面与移动端共用角色和导航规则。

手机对话头部将助手名称与上下文工具分行排列，避免工具按钮挤压名称。

## 助手任务便签

平台助手、Team Leader 私聊及 Team 群聊右侧提供可收起、展开的任务便签。宽屏默认展开，窄屏默认显示收起入口，点击后以抽屉打开；原有文件、成员等面板打开时便签收起，避免挤占对话。

- 平台助手汇总当前账号有权查看的项目任务；Team 助手及 Team 群聊限定到当前团队，包含团队项目对话里的确认事项。普通 Worker/Human 私聊不增加便签。
- 按待人工确认、待验收、失败、阻塞、需修订、已分配/进行中、待分配、已完成和已取消分类。
- 待验收依据 `tasks_detail.status=submitted`；工作流节点归一化后的 `in-progress` 或结果 `SUCCESS` 都不能代替验收状态。
- 人工确认来自原有 HITL 收件箱与项目中断；“去确认”返回原对话，“查看任务”进入带有 team 标识的原项目详情，不会自动批准操作。
- 收起后保留待处理数量；出现新的待处理事项时给出站内提醒。事项处理后随原数据源更新，不靠手工清除便签来伪造完成。
- 项目接口和进行中的工作流定期刷新，复用任务中心的查询缓存。更新失败时提示数据待更新，不显示成“没有任务”。

## 回归关注点

- Admin 默认助手、Team Leader 默认私聊、显式深链接的优先级。
- 消息发送、草稿、读位置、编辑、重试、执行过程、确认卡和话题。
- 任务、产物、资源、设置和插件路由保留。
- 匿名后台重连的 401 不刷新登录表单；已有凭据或有效登录身份对应的 401 仍触发重新登录。
- 登录期间，较早的匿名探测响应不能使新登录的用户退出。

运行 `npm test`、`npm run lint`、`npm run typecheck` 和 `npm run build`，再使用真实账号检查默认入口及原有工具路径。Team 实测需要可用的团队账号与 Leader DM；测试数据验证不能代替真实消息链路验收。

## 视觉节奏

导航与主内容采用清晰分区，取消主内容外层的额外圆角框；卡片、表格和分区线统一使用主题边框，工具栏以无边框的独立按钮区分功能。左侧仅当前子页面使用中性选中底，父分组保留展开状态与文字层级。主要操作采用深灰（深色模式下为浅色），绿色保留给 Logo 和少量语义状态。

标题、界面正文、聊天正文与时间等元信息分层；默认使用 Geist 并补充中文无衬线回退，企业主题的字体与字号覆盖继续生效。模型页的添加操作与数量放在对应标题行，减少单行数据的卡片空高。语音、文件、刷新、通知、主题、设置和对话上下文入口保持独立可达。

设计参考：[Linear 的界面重设](https://linear.app/now/how-we-redesigned-the-linear-ui)、[Intercom Inbox](https://www.intercom.com/help/en/articles/6258745-the-inbox-explained)、[Notion 侧栏整理](https://www.notion.com/releases/2026-03-26)。仅参考分区、对齐与密度，不引入这些产品的协议或额外功能。

## 外观与自动切换

设置 → 外观提供冷灰白、深石墨、暖白和原有高对比度主题，保留跟随系统、自定义主题、导入导出及企业主题能力。默认日间/夜间配色为冷灰白与深石墨；暖白可手动选择，也可作为自动模式的白天配色。

新浏览器默认开启按时间切换，使用设备本地时区，默认白天 07:00、夜间 19:00。开始时间和白天配色可修改并保存，日夜开始时间不能相同。设置仅保存在当前浏览器，不改变服务器时区或其他用户的偏好；已有浏览器明确保存的手动/系统主题继续保留，企业锁定配置优先。

关闭自动模式会固定当前外观；手动选择主题或使用顶栏快捷切换也会退出自动模式。页面刷新前按同一规则预先应用配色，到点、恢复焦点或从休眠返回时重新判断当前时间。自动模式关闭后停止时间监听。

“正在输入”使用输入框正上方的固定高度状态行，与输入内容起始位置对齐，长姓名截断。单人/多人文案依赖真实输入事件，空闲时只保留空白位置，不显示虚构状态；提示切换不改变输入框位置，任务活动信息位于该状态行上方。

## 多团队助手导航

聊天区原有切换行直接显示当前工作范围。多团队用户可在同一处切换团队；单团队用户无需额外菜单。手动选择按当前账号和对话服务地址保存在浏览器，刷新后仅恢复仍可访问的房间；显式任务/房间深链接继续优先。没有有效历史选择时，Admin 进入平台助手，团队用户按固定团队顺序进入已加入的 Leader 私聊，不再跟随最近消息改变默认团队。

新浏览器的会话列表默认按“平台助手 / 我的团队 / 其他对话”组织。团队可展开收起，包含各自的团队助手与团队群聊；Worker、Human、项目房间和原有搜索、空间/群组/私聊筛选仍保留。已有按时间或类型排序的偏好继续生效，也可在“会话排列”中切回团队分组。

Leader 私聊须通过当前用户自己的已加入房间列表核验；Team 资源可见不代表拥有私聊权限。核验中、尚未加入、核验失败或未连接均不打开该 DM，并说明原因；这层入口检查不替代后端授权。团队还有群聊入口时，工作范围切换可进入群聊。补齐的只读 `/api/matrix/joined-rooms` 代理只转发当前用户的 Bearer 凭据，沿用服务地址允许列表，并禁止缓存成员资格。权限每 15 秒刷新，恢复焦点时按查询缓存的新鲜度重新核验；权限撤销后当前 DM 不再保持打开。

团队选择器与团队分组显示各自的待确认、待验收、失败数量，独立于消息未读。复用任务便签的原始状态和共享查询缓存；请求失败显示任务数据待更新，确认仍返回原对话，不自动批准。手机会话列表使用实体背景的模态抽屉，支持 Escape、焦点限制和关闭后焦点恢复。
