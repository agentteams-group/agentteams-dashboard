# Agent 工作区

登录后的主入口是与 Agent 的持续对话。平台管理员使用平台助手，团队用户使用已有的 Team Leader 私聊。对话仍由原有服务承载，不创建另一套会话或任务数据。

## 入口与权限

- 打开产品根路径时进入对话；带有页面或会话标识的深链接继续生效。
- 管理员优先打开平台 Manager 的对话。
- 团队用户从有权访问的 Team 数据读取 `leaderDMRoomID`，不依赖全局 Manager 列表。
- Team Leader 的身份与运行时优先由现有 Worker 数据补全，兼容 Manager 作为 Leader 的数据。
- 非管理员不请求全局 Managers、Humans，平台助手也不会作为团队用户的默认入口。
- 所有操作继续使用原有登录、服务端权限校验和 Controller 凭据。
- Leader DM 的实际访问仍由房间成员权限决定：当前 Controller 为 Team Admin 与 Leader 建立私聊，旧团队回退为平台 Admin 与 Leader；团队资源可见不等于已加入该私聊。

## 界面结构

| 位置 | 内容 |
| --- | --- |
| 助手 | 平台助手或 Team Leader 私聊，切换对话可进入其他助手及群聊 |
| 工作台 | 左侧子菜单：待你处理、任务看板、产物、编码执行、自动化 |
| 资产中心 | 左侧子菜单：模型、工具、技能、知识库；工具复用原 MCP 管理 |
| 成员与团队 | 左侧子菜单：Agent、团队、用户与 Manager；管理功能及权限范围不变 |
| 设置 | 左下常驻；管理页提供总览、审计及插件贡献的监控、诊断等入口；插件页保留插件目录、安装与配置 |
| 顶栏 | 全局搜索、创建、通知、账号、主题、设置和插件工具 |
| 对话侧面板 | 任务、成员、文件、话题、空间概览 |

全部对话列表通过「切换对话」展开。协议名称不占据主对话界面，消息服务配置保留在高级连接设置中。Worker 头像的运行时会话入口仍然保留。

桌面侧栏与移动导航抽屉共用四个主菜单；工作台、资产中心、成员与团队点击展开或收起子菜单，子页面直接在左侧选择，右侧不再重复显示分类 Tab。侧栏整体仍可收起为图标，点击分组图标先展开导航。插件菜单保留在设置中。原有 section 和深链接继续保留，新增 `#console/resources/tools` 可直达工具页。设置中打开审计、总览或插件页面会先关闭设置弹窗；键盘主导航快捷键与四项菜单对应。旧经典导航切换控件由统一四项布局替代。

AT 绿色为默认主色；亮色、暗色、高对比度和企业主题继续使用原有主题机制。桌面与移动端共用角色和导航规则。

手机对话头部将助手名称与上下文工具分行排列，避免工具按钮挤压名称。

## 助手任务便签

平台助手、Team Leader 私聊及 Team 群聊右侧提供可收起、展开的任务便签。宽屏默认展开，窄屏默认显示收起入口，点击后以抽屉打开；原有文件、成员等面板打开时便签收起，避免挤占对话。

- 平台助手汇总当前账号有权查看的项目任务；Team 助手及 Team 群聊限定到当前团队，包含团队项目对话里的确认事项。普通 Worker/Human 私聊不增加便签。
- 按待人工确认、待验收、失败、阻塞、需修订、已分配/进行中、待分配、已完成和已取消分类。
- 待验收依据 `tasks_detail.status=submitted`；工作流节点归一化后的 `in-progress` 或结果 `SUCCESS` 都不能代替验收状态。
- 人工确认来自原有 HITL 收件箱与项目中断；“去确认”返回原对话，“查看任务”进入带有 team 标识的原项目详情，不会自动批准操作。
- 收起后保留待处理数量；出现新的待处理事项时给出站内提醒。事项处理后随原数据源更新，不靠手工清除便签来伪造完成。
- 项目接口和进行中的工作流定期刷新，复用任务中心的查询缓存。更新失败时提示数据待更新，不显示成“没有任务”。

## 回归关注点

- Admin 默认助手、Team Leader 默认私聊、显式深链接的优先级。
- 消息发送、草稿、读位置、编辑、重试、执行过程、确认卡和话题。
- 任务、产物、资源、设置和插件路由保留。
- 匿名后台重连的 401 不刷新登录表单；已有凭据或有效登录身份对应的 401 仍触发重新登录。
- 登录期间，较早的匿名探测响应不能使新登录的用户退出。

运行 `npm test`、`npm run lint`、`npm run typecheck` 和 `npm run build`，再使用真实账号检查默认入口及原有工具路径。Team 实测需要可用的团队账号与 Leader DM；测试数据验证不能代替真实消息链路验收。
