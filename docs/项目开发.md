# AgentTeams Dashboard 项目（Projects）开发指南

本文档面向 Dashboard 贡献者：项目功能的代码结构、API 客户端、缓存策略、降级语义、扩展点。

> 用户视角（怎么用、怎么干预、怎么下载产物、怎么查历史）见 [`项目.md`](./项目.md)。

**共享基础**：

- `api-base.ts:requestJson` / `extractErrorDetail` —— 所有 agentteams 客户端统一 fetch 模式与错误形态（ApiError 带 upstream status）
- `api-error.ts:loadErrorMessage` —— 通用错误文案装载（用户可读）

## 2. 数据流

```
ProjectsSection
  ├─ useProjects() ───────────────┐
  └─ useProjectWorkflow(id, team) │   15s refetchInterval
                                  │
useApiTaskBoard (TasksSection)    │   ≤20 projects → per-project workflow
  ├─ useProjects() ──────────────┤   workflowQueries refetch
  └─ useQueries(workflows) ──────┘
                                  ▼
       lib/agentteams-projects-api.ts (client)
                                  ▼
       /api/agentteams/projects/* (proxy)
                                  ▼
       Controller /api/v1/projects/* (#1169 / #1172)
```

**缓存键**（`use-projects.ts:38/62/79/95/112/138`）：

- 列表：`['agentteams-projects']`
- 详情：`['agentteams-project-workflow', teamId ?? 'any', projectId]`
- 所有写操作的 `onSuccess` 都用「请求时的 teamId」写回缓存（不用响应里的 `team_id`），保证请求无 teamId 时也能命中订阅键

**写操作缓存更新模式**（`use-projects.ts:67-144`）：

1. mutation 返回 Controller 刷新的 workflow
2. `setQueryData` 立刻把详情缓存填上（用户视角「立即生效」）
3. `invalidateQueries` 触发 list 重拉

## 3. 复合身份 `(team, project_id)`

`agentteams-projects-api.ts:179-194` 显式处理：

- `getProjectWorkflow({ teamId })`：可选 query；不传时 Controller 返 409（同一 id 跨 team 歧义）
- 所有写操作 `mutationUrl` / `cancelProjectTask` 都把 `teamId` 拼到 query
- 详情面板 `useProjectWorkflow(projectId, teamId)`：teamId 来自列表条目；如果失败则回退到 `wf?.team_id`（`projects-section.tsx:386`）
- 409 在 UI 单独提示「该项目 id 在多个团队下存在」（`projects-section.tsx:481-498`），不归并为通用错误

`isSameProject`（`projects-section.tsx:865-874`）接受选择态 `{ id, team }` 和 API 态 `{ project_id, team_id }` 两种 shape 做比对。

## 4. 降级语义

### 4.1 List 降级

`api/agentteams/projects/route.ts:33-68`：

- Controller 5xx → `degradedReason: 'controller-error'`（「端点存在但调用失败」）
- Controller 4xx（含 404）→ `degradedReason: 'api-not-deployed'`（「Controller 未升级」）
- 两种情况都返 `{ projects: [], total: 0, error, degraded: true, degradedReason }`，**HTTP 200**

**消费者**：

- `ProjectsSection` 用 `DegradedBanner`（`projects-section.tsx:337-361`）显示差异化提示
- `useApiTaskBoard` 把 `degraded || isError` 视为降级，自动 fallback 到 MinIO 直读看板（`tasks-section.tsx:511-515`）

### 4.2 Workflow 降级

`api/.../workflow/route.ts:18-36`：透传 Controller 4xx/5xx（不假装成降级），让前端区分「项目不存在」与「API 不可用」。

### 4.3 History 降级

`api/.../history/route.ts:19-37`：透传 4xx/5xx。`ProjectTimelinePanel` 的 `useEffect` 内 catch 错误时，`loadErrorMessage(e, '时间线加载失败')` 触发灰色降级文案，**不**冒泡到项目主面板（`project-timeline-panel.tsx:45-64`）。

## 5. 写操作的错误透传

`projects-section.tsx:325-333` 的 `toastMutationError`：

- `ApiError` → `项目{action}失败（HTTP {status}）` + Controller 返回的 `message`
- 其他错误 → 通用文案 + 错误字符串

Controller 4xx 错误体支持两种 schema：`{ message }`（httputil.ErrorResponse）和 `{ error }`（middleware）。`api-base.ts:extractErrorDetail` 已统一处理；`ArtifactLink`（`projects-section.tsx:263-312`）也用同样逻辑避免把错误体当文件下载。

## 6. 缓存与刷新策略

| 资源 | 轮询 | 说明 |
|---|---|---|
| `useProjects` | 15s | `placeholderData: previousData` 避免列表闪烁 |
| `useProjectWorkflow` | 15s | `enabled: !!projectId`；不在首页时不拉 |
| `useApiTaskBoard.workflowQueries` | `staleTime: 15s` | 20 项目上限硬编码（`use-projects.ts:261`） |
| `useTaskBoard`（MinIO 兜底） | 8s | 仅在 `apiBoard.degraded` 时 `enabled: true` |

`useApiTaskBoard.refetch`（`use-projects.ts:299-305`）同时清掉 list 和所有 workflow，避免 list 刷新但 workflow 留旧。

## 7. 扩展点

项目模块当前**没有专门的插件扩展点**（不像 `sidebar-menu` / `route` / `dashboard-widget` 那套）。如果需要：

- **新增详情面板区块**（比如依赖图、时间线之外的新面板）→ 在 `projects-section.tsx:WorkflowDetail` 内增加新子组件，复用 `useProjectWorkflow` 的 cache key 即可
- **新增项目状态相关的通知** → 监听 `useAgentTeamsStore` 的变化或在 `use-phase-watcher` 加新 phase
- **新增写操作**（如 `archive` / `delete`）→ 仿照 `use-projects.ts:67-144` 加一个 mutation + `api/.../projects/[id]/{action}/route.ts` proxy

## 8. 类型契约

`agentteams-projects-api.ts:1-19` 显式声明字段对照：

- `WorkflowResponse` ↔ `project_handler.go` `workflowResponse`
- `WorkflowInterrupt` / `InterruptActionRequest` / `InterruptConfig` ↔ 同上 `workflowInterrupt` / `interruptActionRequest` / `interruptConfig`
- `WorkflowTaskDetail` ↔ `taskDetail`
- `WorkflowLoop` / `WorkflowLoopTask` ↔ `loopMeta` / `projectTaskMeta`

**Controller 改 schema 时**：

1. Controller PR 必须同步更新 `docs/zh-cn/usage/project-workflow-api.md`
2. Dashboard 这边的 `WorkflowResponse` 等类型必须同步更新
3. 涉及 `tasks_detail` / `loop.tasks` / `interrupts.action_request` 这三个非平凡字段，UI 侧 narrow + 防御性默认值要复查

## 10. 已知约束与待办

1. **没有 `createProject` 客户端 / 端点**：Dashboard 不实现创建（详见 [`项目.md` §3](./项目.md#3-怎么创建项目)）。如要加，先确认 Controller 端有 `POST /api/v1/projects`
2. **`useApiTaskBoard` 20 项目上限**硬编码在 `use-projects.ts:261`，UI 上没暴露「显示更多」
3. **`WorkflowDagView` 没被导出复用**（仅在 `projects-section.tsx:1086` 内部用），如 workbench 插件想直接用需拆出独立模块
4. **replan 字段映射在 client 侧做**（`projects-section.tsx:444-462`），与 Controller 真实 snake_case 字段名有差异；Controller schema 变更时需同步
5. **没有 `restore` / `create` checkpoint 写端点**：worker checkpoint 面板纯只读，需 Controller 端先开
