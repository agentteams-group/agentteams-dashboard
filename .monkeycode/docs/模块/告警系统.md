# Alert System Module

告警系统是 AgentTeams Dashboard 的可观测性扩展模块，将 insights-engine 检测到的异常通过 Matrix、Slack、Email 等渠道通知运维人员。

## 核心组件

### AlertManager

路径：`src/lib/alert-manager.ts`

中央协调器，负责：
- 注册和管理 AlertRule
- 评估洞察是否应触发告警（severity + throttle 检查）
- 调度通知发送到配置渠道
- 追踪失败通知供人工排查

关键方法：
- `registerRule(rule)` / `getRule(id)` / `getAllRules()`
- `shouldSend(rule, insight)` — 检查 severity 阈值和节流窗口
- `send(payload, rule, adapters)` — 异步发送通知并处理重试
- `markAsSent(insightId)` — 更新节流时间戳
- `getFailures()` / `clearFailures()` — 管理失败日志

### Notification Adapters

路径：`src/lib/notifications/`

插件式适配器架构：

| Adapter | 文件 | 说明 |
|---------|------|------|
| Base | `base-adapter.ts` | 抽象基类，定义 AdapterConfig 接口 |
| Matrix | `matrix-adapter.ts` | 通过代理发送到 Matrix 房间 |
| Slack | `slack-adapter.ts` | 调用 Slack Incoming Webhook，支持 severity-based color |
| Email | `email-adapter.ts` | 调用 REST API (SendGrid/SES)，支持多收件人 |

### Alert Types

路径：`src/lib/alert-types.ts`

核心类型定义：
- `AlertSeverity`: 'info' | 'warning' | 'critical'
- `AlertChannel`: 'matrix' | 'slack' | 'email'
- `AlertRule`: 告警规则配置
- `NotificationPayload`: 通知消息载荷
- `AlertFailure`: 失败记录

### Alert Rules Store

路径：`src/lib/alert-rules.ts`

使用 localStorage 持久化告警规则：
- `loadAlertRules()` / `saveAlertRules(rules)` — 读写规则
- `buildDefaultRules()` — 生成覆盖所有常见洞察类型的默认规则
- `getOrInitializeRules()` — 首次访问时初始化默认规则

### Insight to Alert Bridge

路径：`src/hooks/use-insights-alerts.ts`

React Hook，在 Dashboard 挂载时：
- 初始化 AlertManager 规则
- 监听新的 insights（severity >= warning）
- 自动路由到匹配的告警规则
- 异步 dispatch 发送通知

## API 端点

路径：`src/app/api/settings/alerts/route.ts`

RESTful API 用于管理告警规则：
- `GET /api/settings/alerts` — 获取所有规则
- `POST /api/settings/alerts` — 创建新规则
- `PUT /api/settings/alerts` — 更新现有规则
- `DELETE /api/settings/alerts?id=<id>` — 删除规则

## UI 组件

路径：`src/components/dashboard/settings/alert-settings.tsx`

嵌入在 Settings Dialog 的"告警"标签页：
- 展示规则列表（severity badge + 渠道信息）
- 编辑表单（洞察类型下拉、渠道多选、节流分钟数输入）
- 启用/禁用开关
- 新建/删除操作

## 正确性属性

1. 每个告警规则至少关联一个有效 channel
2. 相同告警在 throttleMinutes 内最多发送一次
3. Critical 级别告警必须有至少一条通知渠道
4. 通知发送失败自动重试（最多 3 次，退避 1s/2s/4s）
